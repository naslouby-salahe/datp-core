# REVIEWER_4 — Scientific invariants, reuse, typing, config

Scope: `git diff origin/main` over `campaign.py`, `personalization.py`, `temporal.py`, `confirmatory.py`, `external.py`, `cli/app.py`, `cli/execution.py`, `domain/enums.py`. All claims verified against `docs/Journal_Extension_Master_Roadmap.md` and the source; no tests run.

## Findings

- [SEV-MED] `src/datp_core/pipeline/workflows/campaign.py:957-966` — new `_ditto_analysis_marker_present` hardcodes the root segment `"ditto_stress_test"` (L961) and `"analysis"` (L963) even though `ExecutionRootDirectory.DITTO_STRESS_TEST` (value `"ditto_stress_test"`, `layout.py:23`) is already imported in this module (L38) and `personalization.ditto_directory()` is the canonical path builder. Roadmap/CLAUDE rules: §10.1 "Do not hardcode … path fragments" and §5 reuse-first. The `_temporal_analysis_marker_present` twin (L969-985) correctly uses `ExecutionRootDirectory.BOUNDED_EVIDENCE`, so the Ditto marker is an avoidable reuse miss in new code. The raw string matches the enum value today, so status derivation is still correct; it is a contract/reuse defect, not a wrong result.

- [SEV-LOW] `src/datp_core/pipeline/workflows/campaign.py:943-954` — new `_fedprox_analysis_marker_present` hardcodes `"fedprox_stress_test"` (L945), `"primary_coefficient_decision.json"` (L946), `"analysis"` (L950) and the role tuple `("primary","sensitivity")` (L951), duplicating the same literals already present in the pre-existing `_report_fedprox_absorption` (L799, L802, L818). No `ExecutionRootDirectory.FEDPROX_STRESS_TEST` exists, so this extends existing raw-string debt rather than creating a fresh mismatch, but the duplicated decision-file/role names are single-source-of-truth violations (§10.1, §5). Low because the strings are consistent with the writer.

- [SEV-LOW] `src/datp_core/pipeline/workflows/campaign.py:364-381` — `_dispatch_ditto_absorption_stress_test` hardcodes `completed = (SHARED_THRESHOLD, LOCAL_THRESHOLD)` (L364-367) and feeds `completed_by_seed=(completed,) * len(seeds)` (L379) into `_seed_completion_outcomes`, discarding the `DittoStressTestResult` objects returned by the loop (L368-374). Every other dispatcher derives completion from the actual result (`FedProxStressTestResult.completed_threshold_methods`, `BoundedExternalSeedResult.completed_threshold_methods`, `ConfirmatorySeedResult.completed_threshold_methods`). It is truthful today only because `run_ditto_stress_test_seed` hard-raises unless both thresholds construct as `SharedThresholdResult`/`LocalThresholdResult` (personalization.py:354-363); a change to that contract would silently report COMPLETED for a non-completed method. Robustness/derivation defect, not an actual mis-statement.

- [SEV-LOW] `src/datp_core/domain/enums.py:191-195` — new `ThresholdMethodExecutionStatus` members `UNAVAILABLE = "unavailable"` and `INFEASIBLE = "infeasible"` duplicate string values already declared in `AvailabilityStatus` (L184-188) and `ExperimentReadiness` (L32). Per §8.1 "Never duplicate the same vocabulary in multiple enums." The 4-member StrEnum itself is present and correctly typed, and the domain is distinct (per-method execution status vs metric availability), so this is a letter-of-the-rule violation only. Additionally, `FAILED` is never constructed anywhere in the diff (only COMPLETED/UNAVAILABLE/INFEASIBLE are emitted by `_seed_completion_outcomes`/`_temporal_method_outcomes`); it is a reserved-but-unused member, not a bug.

- [SEV-LOW] `src/datp_core/pipeline/workflows/personalization.py:157-198` and `src/datp_core/pipeline/workflows/temporal.py:264-299` — the new Ditto evidence persist/load and temporal evidence persist/load implement the identical pattern (write `seed.json` via `canonical_json_text`, write `COMPLETE` via `canonical_checksum`, then load via `TypeAdapter.validate_json` + checksum re-verify). §5/§6 favor consolidation of the shared checksum-protected evidence round-trip; the duplication is small and type-specific, so low. The integrity mechanism itself (checksum binding between `seed.json` and `COMPLETE`, hard error on mismatch) is sound and is the correct fixed-evidence design.

## Verdict

The diff is a sound execution-foundation change: it keeps detector training strictly in the run path (reports now consume checksummed persisted evidence, deleting the two re-training campaign wrappers), removes optional-output-root fallbacks, threads `output_root` so smoke no longer pollutes real outputs, strengthens the analysis-marker guard, and introduces no new hardcoded scientific values, hidden defaults, or `Any`. No scientific-invariant violation was found. The only substantive defect is a reuse/configuration one: the new Ditto and FedProx analysis-marker functions hardcode path fragments — `"ditto_stress_test"` even though `ExecutionRootDirectory.DITTO_STRESS_TEST` is imported in the same module — rather than reusing the layout enum/helper, plus minor pattern-level issues (Ditto dispatch asserts completion instead of deriving it; duplicate evidence-persist logic; enum-value vocabulary overlap and a reserved-but-unused `FAILED` member). None of these change any executed scientific result today.
