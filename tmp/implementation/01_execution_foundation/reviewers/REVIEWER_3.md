# REVIEWER_3 — Outcome surfacing, status semantics

Dimension: threshold-method outcome surfacing + analysis-completion/status semantics. Read-only review of working-tree diff vs origin/main (76afa5c).

## Findings

- [SEV-MED] src/datp_core/pipeline/workflows/campaign.py:400-404,419 — `_temporal_method_outcomes` builds `completed` as a **union across all three states and all seeds** (`completed.update(state.completed_threshold_methods)`) but labels any member COMPLETED with detail "executed across all temporal states and seeds". The three states use different calibration roles — static/frozen use `PartitionRole.CALIBRATION`, recalibrated uses `PartitionRole.FUTURE_RECALIBRATION` (temporal.py:444,449) — so eligibility cohort size differs per state and `GROUP_COUNT_EXCEEDS_ELIGIBLE_POPULATION` availability can differ (thresholding/identities.py:14). A method that completes in static/frozen but is UNAVAILABLE in the recalibrated state (smaller recalibration window) is still surfaced as COMPLETED with the all-states claim. The dispatch outcome therefore can assert a stronger result than `state.completed_threshold_methods` verifies, and it diverges from the recoveries basis: `TemporalSeedResult.__post_init__` restricts `recoveries` to `_common_completed_methods` (temporal.py:143), i.e. methods common to all three states, but the outcome union does not apply the same cross-state agreement. Evidence: `for state in (...): completed.update(...)`. Fix: gate COMPLETED on the method being present in every state's completed list (or surface the partial state in detail) before claiming all-states execution.
- [SEV-LOW] src/datp_core/pipeline/workflows/campaign.py:244-259 — same at-least-once vs across-all-seeds mismatch in `_seed_completion_outcomes`: `completed.update(methods)` across seeds, yet COMPLETED detail is "executed across {len(completed_by_seed)} seeds". If a declared method completed in only a subset of seeds, the detail overclaims all-seed execution. Population-level capability determinism makes completion seed-invariant in practice, but the code does not verify it; detail is stronger than the evidence.
- [SEV-LOW] src/datp_core/pipeline/workflows/campaign.py:364-381 — `_dispatch_ditto_absorption_stress_test` **asserts** `completed = (SHARED_THRESHOLD, LOCAL_THRESHOLD)` and passes `(completed,) * len(seeds)` instead of deriving outcomes from the per-seed results (the loop discards the returned `DittoStressTestResult`). This is safe today only because `run_ditto_stress_test_seed` raises `ScientificContractError` on any non-`SharedThresholdResult`/`LocalThresholdResult` construction (personalization.py:354-363), so no alternative status can arise — but it is the sole handler that fabricates rather than reads outcomes, and `DittoStressTestResult` carries no `completed_threshold_methods` field to source it from. Inconsistent with every other handler; keep an eye on it if Ditto ever gets an availability path.
- [SEV-LOW] src/datp_core/pipeline/workflows/campaign.py:258,424 — INFEASIBLE detail is hardcoded as "declared but unsupported by the population capability contract" without verifying the planner disposition. For FedProx the campaign is built from coordinates filtered to `model_coefficient is not None` (personalization.py:496-503), so a declared method excluded by that filter (not by capability) would still be labeled capability-unsupported. Detail is an unverified claim; status itself (INFEASIBLE for not-completed) is correct per ledger.
- [SEV-LOW] src/datp_core/pipeline/workflows/campaign.py:350 — FedProx COMPLETED detail "executed across {len(completed_by_seed)} seeds" counts seed×coefficient runs, not seeds: full campaign is 10 seeds × 4 coefficients = 40, so the string reads "executed across 40 seeds". Cosmetic overstatement.
- [SEV-LOW] src/datp_core/pipeline/workflows/temporal.py:543-547 — `_evaluate_state` raises `ScientificContractError("temporal execution produced no evaluable threshold method")` when ALL declared methods are unavailable in a state. Per-method unavailability is handled without raising (temporal.py:475-483), but a total-unavailability state fails the run instead of surfacing all-UNAVAILABLE outcomes. Acceptable fail-closed design for the current 4-method temporal ladder (SHARED/LOCAL will be feasible), but it is technically a runtime failure on full unavailability; worth confirming the ledger intends fail-closed here.
- [SEV-LOW] src/datp_core/pipeline/workflows/campaign.py:929-940 — `_fedprox_analysis_marker_present` accepts `publication.md` under *either* `primary` or `sensitivity` per coefficient (`any(... for role in ...)`) without checking the role matches the current `primary_coefficient_decision.json`. A stale role directory from a prior run (different primary) still yields ANALYSIS_COMPLETE. Presence semantics; mild staleness window.

## Verdict

WR-008 and WR-009 are structurally implemented and verified: every dispatch handler surfaces an outcome per declared threshold method, the temporal dispatch derives outcomes from live per-seed runs (not from re-loading the 10-seed campaign), temporal unavailability is carried as UNAVAILABLE with reason+detail instead of raising, all 7 registered workflows have exactly-matching analysis-marker checks enforced by `frozenset` equality, the marker predicates align with the actual report/analysis artifact paths, `programme_status` is read-only and follows the specified status ladder, `anchor_status` degrades to BLOCKED instead of raising on a missing gate, and the campaign completion marker is written only after all experiments run. I found no demonstrated bug that breaks the ledger contract. The defects I would act on are the at-least-once-vs-all-states/seed overclaim in `_temporal_method_outcomes` (campaign.py:400-404, detail 419), where a method unavailable in the recalibrated state can still be surfaced as COMPLETED "across all temporal states and seeds" because the union ignores the cross-state agreement that `_common_completed_methods` enforces elsewhere; and the Ditto handler's fabricated (asserted, not derived) COMPLETED outcomes. Both are risk/low-severity rather than confirmed failures, but the temporal one is the only place the surfaced status can diverge from what the persisted evidence actually supports, so it should be tightened before this is treated as finished.
